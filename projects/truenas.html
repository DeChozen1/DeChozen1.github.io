Nextcloud NAS

A self-hosted Nextcloud AIO service running on Proxmox, with HTTPS, private remote access and an existing 4TB media drive exposed as external storage. The next phase is cloud-data migration and a separate backup drive.

Proxmox VE Nextcloud AIO Caddy Cloudflare DNS WireGuard SMB / CIFS

Overview

The original plan was to run a virtual TrueNAS NAS for storage, backups and local file access. After troubleshooting repeated UEFI and virtual-console installation issues, the TrueNAS VM was removed and the project shifted to Nextcloud AIO for private file access, including large action-camera videos from an iPhone.

The Nextcloud AIO instance runs in an Ubuntu Server VM on Proxmox. The core Nextcloud service, HTTPS endpoint and AIO containers have been brought up successfully. The existing 4TB media drive is mounted separately and exposed through Nextcloud External Storage, without reformatting the disk.

Current milestone: Core private-cloud service operational. OneDrive and Google Drive data migration remains pending. An independent backup or redundancy design is not yet complete, so this is not yet a fully backed-up storage system.

Build Log

Initial TrueNAS VM Troubleshooting

The installer first failed with a UEFI Access Denied message. Secure Boot and EFI settings were investigated, including recreating the EFI disk. A later attempt produced corrupted-looking coloured lines in the installer console, so the investigation moved to the Proxmox virtual display and serial-console settings. The VM was eventually removed and the project moved to Nextcloud AIO.

Nextcloud AIO Deployment

  • Imported and configured the Nextcloud AIO appliance in an Ubuntu Server VM on Proxmox.
  • Configured the AIO data directory as /mnt/ncdata and exposed its Apache backend on port 11000 for the reverse proxy.
  • Configured cloud.dechozen1.stream for Nextcloud access.
  • Confirmed the AIO application containers were healthy after a stop/start through the AIO interface.

HTTPS, Caddy and Cloudflare DNS Challenge

  • Installed a custom Caddy build with the Cloudflare DNS provider plugin and configured Caddy to reverse-proxy requests to Nextcloud AIO.
  • Initial certificate attempts failed because the DNS provider tried to identify the zone as stream. instead of dechozen1.stream.
  • Added resolvers 1.1.1.1 to the Caddy TLS configuration. The DNS-01 challenge then succeeded and Let's Encrypt issued the certificate.
  • Fixed Caddy service access to its configuration by setting /etc/caddy to root:caddy mode 750 and the Caddyfile to root:caddy mode 640. The Cloudflare token remains in a root-protected environment file loaded by systemd.
  • Confirmed Caddy listens on ports 80 and 443, while the Nextcloud AIO backend remains on 11000. HTTPS redirects to the Nextcloud login page.

Private Remote Access

  • Kept the intended remote access path on the existing WireGuard VPN rather than using public port forwarding or Cloudflare Tunnel.
  • Checked the ASUS router: port forwarding was off, the forwarding table was empty, and DMZ was disabled.
  • Verified remote access from a phone using mobile data with the WireGuard tunnel enabled; the HTTPS Nextcloud login page loaded successfully without router port forwarding.

Existing 4TB Drive and External Storage

  • Preserved the existing Seagate 4TB media disk, formatted as exFAT. It is mounted on the Proxmox host at /mnt/check4tb; its media content must not be formatted or overwritten during future storage changes.
  • Created a restricted Samba share named NextcloudMedia on the Proxmox host, pointing to /mnt/check4tb/English and allowing the Nextcloud VM at 192.168.50.145.
  • Mounted the SMB share in the Nextcloud VM at /mnt/ncmedia-test using CIFS. Read/list access was confirmed, and a direct SMB upload test succeeded.
  • Added the share to Nextcloud External Storage as 4TB Media. The media folder listing appeared in Nextcloud.
  • During permission troubleshooting, the external-storage mount was checked from both the VM and the Nextcloud application container. A write test as www-data succeeded after restarting the relevant application container.
  • A web copy operation into 4TB Media/Movies appeared to stall. The associated PHP-FPM worker was identified and sent SIGTERM; the worker exited. The destination should be inspected for partial files before retrying any transfer. Do not assume the interrupted copy was rolled back.
  • The CIFS mount and host mount are not yet confirmed as persistent across reboot. Persistence and a clean end-to-end folder-creation/copy test remain follow-up tasks.

Milestone Update — 14 October 2026, 12:49 AM SGT (UTC+8)

Status: Core service operational; migration and backup pending. Nextcloud AIO is running, the HTTPS login endpoint is available, and the existing 4TB media share is visible through Nextcloud External Storage. The service is ready for carefully staged migration work, but the interrupted copy needs a destination check and the storage mounts need persistence validation.

  • Operational: Proxmox-hosted Ubuntu VM, Nextcloud AIO, Caddy HTTPS reverse proxy and configured external SMB media storage.
  • Pending data migration: OneDrive and Google Drive files have not yet been fully migrated and verified.
  • Pending storage hardening: Add a second 4TB drive and implement a verified backup or redundancy plan.
  • Safety note: A second disk in a ZFS mirror can provide single-drive-failure tolerance, but a separate backup is still needed to protect against accidental deletion, corruption or other unwanted changes.

Next Steps

  1. Inspect 4TB Media/Movies for partial results from the interrupted copy; compare source and destination before retrying.
  2. Make the host exFAT mount and VM CIFS mount persistent, then reboot-test them carefully without formatting the existing disk.
  3. Check the Nextcloud VM's actual filesystem and free space before choosing the destination for OneDrive and Google Drive migration.
  4. Copy cloud data in stages and verify folder structure, file counts, file sizes and important files before deleting anything from the original cloud accounts.
  5. Acquire a second 4TB drive and create a verified independent backup. Consider a ZFS mirror later if automatic tolerance of a single disk failure is desired.
  6. Do not cancel OneDrive or Google Drive subscriptions until the migration is checked and the backup has been tested.
