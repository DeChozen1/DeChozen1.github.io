Documentation

Proxmox Management NIC Connectivity Issue

During testing, the Proxmox management interface intermittently lost network connectivity after extended periods of uptime. The server itself remained running, but the Proxmox management interface would become unreachable from the network.

Reconnecting the Ethernet cable temporarily restored connectivity. This indicated that the issue needed to be investigated at the network interface and link level rather than being treated as a virtual machine failure.

Environment

The Proxmox host is a Dell Precision T5810 running an Intel Xeon E5-2680 v4 with 64GB RAM. The onboard Ethernet interface is used for Proxmox management, while the additional 10GbE NIC is used for the high-speed network configuration.

Investigation

I traced the connection from the physical Ethernet port through the Linux network interface and Proxmox bridge configuration. The onboard management NIC was confirmed as the interface connected to the router, while the separate 10GbE interfaces served the lab's high-speed networking requirements.

  • Verified which physical NIC was being used for Proxmox management.
  • Checked the Linux network interface and link state.
  • Verified the Proxmox bridge and management network configuration.
  • Tested connectivity between the Proxmox host and the router.
  • Compared behaviour after physically reconnecting the Ethernet connection.
  • Adjusted the network configuration so the management connection would remain persistent instead of requiring manual cable reconnection.

Network Path

The management connection follows this path:

ASUS Router → Onboard NIC → Proxmox Network Bridge → Proxmox Management Interface

This is kept separate from the additional 10GbE networking used by the virtualised network infrastructure.

Result

After investigating and adjusting the network configuration, the Proxmox management connection became stable without requiring repeated physical reconnection of the Ethernet cable.

This troubleshooting process also reinforced the importance of separating physical link issues, Linux interface state, bridge configuration and virtual machine networking when diagnosing Proxmox connectivity problems.

Lessons Learned

  • Identify the physical NIC before troubleshooting the Proxmox bridge or virtual machines.
  • Separate physical link problems from virtual networking problems.
  • Check the host's network state before assuming a VM or service is responsible for the outage.
  • Network fixes should be persistent rather than relying on physically reconnecting cables.
  • Keeping management networking separate from high-speed lab networking makes troubleshooting easier.
