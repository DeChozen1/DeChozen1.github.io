Bucks Finance

A self-hosted personal finance application built to make monthly cash flow, category budgets, recurring obligations, loan balances and savings goals easier to track in one private place.

Python FastAPI PostgreSQL SQLAlchemy Docker Compose Jinja2

Overview

Bucks started as a small personal finance tool and has grown into a month-aware app with a dedicated transaction workflow, category budgets, fixed bills, loan payments, one-off commitments, plans and savings contributions. It runs as a containerised web application backed by PostgreSQL.

Current milestone: Version 2.2.1 is running in the private homelab. The overview includes charts, and variable expenses are designed to flow through category budgets rather than being treated as fixed bills. The source is kept in a private repository.

The public project notes intentionally omit account balances, transaction history, internal host addresses and deployment credentials.

Architecture

  • Application: Python with FastAPI, server-rendered Jinja2 templates and custom CSS.
  • Persistence: PostgreSQL with SQLAlchemy models for monthly records and finance workflows.
  • Deployment: Docker Compose with separate application and database services, plus a persistent database volume.
  • Configuration: Secrets and administrator credentials are provided through environment variables rather than stored in source code.
  • Privacy: Intended for private self-hosting and access through the home network or VPN, not direct public exposure.

Implemented Features

Monthly overview and charts

The dashboard brings income, bills, obligations and tracked spending into a single monthly view. Visual summaries include spending-category breakdowns, budget-versus-spent progress and an income-versus-outflow trend. Month selection is intended to keep records separated by period.

Budgets and transactions

Variable expenses such as groceries and fuel belong in monthly category budgets. Transactions are categorised, and eligible expenses reduce the matching budget for that month. Editing or recategorising a transaction should update the category totals rather than requiring a second manual adjustment.

Bills and one-off commitments

Predictable obligations remain separate from discretionary category budgets. One-off commitments have their own month and paid status so planned purchases or upcoming expenses can be tracked without turning every variable purchase into a bill.

Loans, plans and savings

Loan payments distinguish principal reduction from interest and retain payment history. Plans and savings funds track goals and contributions independently, helping avoid treating a contribution as both spending and available cash.

Transaction import and export

Transactions can be entered individually, imported from a CSV, and exported for personal record-keeping. Exported data is treated as sensitive and should stay out of source control.

Build Log

Initial application

The first version was built with FastAPI, SQLAlchemy and PostgreSQL, with a login screen and pages for salary, bills, loans, commitments, plans and transactions. Docker Compose separated the application from the database.

Month-aware finance workflows

The data model was expanded to preserve monthly bill and loan snapshots, one-off commitments and transaction records. Additive schema changes were used so existing records could be retained as new workflows were added.

Budgets and dashboard

Variable-spending budgets were introduced alongside transaction categories, with an overview designed to distinguish budget remaining from the projected monthly balance. Charts provide a quick visual view of allocation and spending trends.

Operational safeguards

  • PostgreSQL data is stored in a persistent Docker volume.
  • Database and application-code backups are made before upgrades.
  • Example environment variables use placeholders; live secrets and financial records are excluded from the source repository.
  • Schema changes are designed to add new tables or fields rather than erase existing records.

Current Status

Active development · v2.2.1 running. The current milestone is a usable private finance tracker with budgets, transaction categorisation, loan and savings workflows, and a chart-based overview. Future work should focus on stronger authentication hardening, automated regression checks, import validation and documented recovery drills.

Security and Privacy Notes

  • Do not commit environment files, credentials, database dumps, transaction exports or screenshots containing real financial data.
  • Keep the service on a trusted private network or VPN. Do not publish the live instance or expose its port directly to the Internet.
  • Use unique strong database, administrator and session secrets, and keep backups separate from the application source.
  • Before any untrusted or wider deployment, perform a dedicated security review of session configuration, authentication throttling, input validation and HTTPS settings.

This is a personal self-hosted project, not a regulated banking service or a hardened multi-user financial platform. The public page contains no real account data or private deployment details.
