OPNsense Firewall & Network

Virtual firewall/router used to experiment with routing, DHCP, DNS, IDS/IPS and multi-gig networking.

OPNsense Routing DHCP IDS/IPS

Overview

The OPNsense VM sits on the Dell T5810 and handles the routing and security layer of the homelab. The project has included interface and bridge configuration, DHCP/DNS work, monitoring and IDS/IPS testing while troubleshooting connectivity between the ISP, firewall, router and Proxmox management path.

Documentation

OPNsense Passthrough Configuration

OPNsense is being prepared as the primary firewall and routing layer for the homelab. The current configuration work has focused on moving the network interfaces required by OPNsense through Proxmox so the virtual firewall can directly handle the relevant network connections.

The passthrough configuration has been completed at the virtualisation layer, but the physical connections have not yet been moved over for live testing.

Current Network Architecture

The planned network path places OPNsense between the ISP connection and the main ASUS router. The Dell T5810 provides the virtualisation platform, while the dedicated network interfaces are being assigned to the firewall VM.

The current design is intended to provide a clear separation between the Proxmox management connection and the interfaces used by the OPNsense firewall.

Implementation

  • Created the OPNsense virtual machine on Proxmox.
  • Configured the VM networking and required Proxmox interfaces.
  • Prepared the physical NICs for passthrough to the OPNsense VM.
  • Configured the required passthrough mapping within Proxmox.
  • Kept the Proxmox management interface separate from the interfaces intended for OPNsense.
  • Prepared the environment for direct physical WAN/LAN testing.

Planned Test

The next stage is to physically connect the network path and test the complete firewall configuration rather than relying only on the virtual configuration.

The planned test will verify whether OPNsense can successfully receive the upstream connection, establish the LAN path and pass traffic through to the ASUS router and connected clients.

What Will Be Tested

  • WAN link detection and connectivity through OPNsense.
  • LAN connectivity from OPNsense to the downstream router.
  • DHCP and DNS behaviour through the new routing path.
  • Internet connectivity from client devices.
  • Proxmox management connectivity while the firewall is operating as the network gateway.
  • IDS/IPS monitoring and traffic visibility once live traffic is passing through the firewall.

Current Status

Passthrough has been configured, but the physical network cutover has not yet been performed. The firewall has therefore not yet been validated as the live gateway for the homelab.

The next milestone is the physical connection and controlled network test. The results of that test will be documented here, including any routing, DHCP, DNS or connectivity issues discovered during the cutover.

Lessons Learned So Far

  • Virtual firewall projects require both correct VM configuration and correct physical network connectivity.
  • Separating management networking from firewall interfaces makes the Proxmox host easier to access during testing.
  • Passthrough configuration can be completed before the physical cutover, allowing the network change to be tested in a controlled manner.
  • The live test is necessary to validate the complete path from the ISP connection through OPNsense to the internal network.
